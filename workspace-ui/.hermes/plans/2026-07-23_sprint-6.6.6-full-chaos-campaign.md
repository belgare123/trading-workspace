## Block 1 — Campaign Engine

Decralative DSL for defining time-sequenced chaos campaigns.

```
campaign("Exchange Outage")
  .at("T+2m").inject({ type: 'latency', scope: REST, minMs: 2000, maxMs: 5000 })
  .at("T+4m").inject({ type: 'timeout', scope: REST, durationMs: 10000 })
  .at("T+5m").inject({ type: 'disconnect', scope: PRIVATE_WS })
  .at("T+6m").assert((ctx) => ctx.assertCircuitBreakerOpen())
  .at("T+8m").recover(REST)
  .at("T+9m").recover(PRIVATE_WS)
  .at("T+12m").assert((ctx) => ctx.assertHealthy())
  .at("T+13m").certify()
  .run()
```

Implements:
- `Campaign` class with `.at()` / `.inject()` / `.recover()` / `.assert()` / `.certify()`
- `CampaignStep` — single step in the timeline
- `CampaignContext` — shared state between steps
- `CampaignResult` — pass/fail per step + aggregate
- `CampaignRunner` — executes steps in sequence with virtual time

## Block 2 — Multi-Failure Scenarios

Pre-built campaign definitions for 4 real-world scenarios:

| Scenario | Description | Profile Composition |
|----------|-------------|---------------------|
| Exchange Slow | REST latency + Public WS latency + Packet loss | EXCHANGE_SLOW + NETWORK_LOSS |
| Network Partition | REST timeout + Private disconnect + Reconnect | TimeoutREST + DisconnectPrivWS + Reconnect |
| Exchange Outage | REST down + WS down + Recovery | Full disconnect → gradual recovery |
| Cascading Failure | Latency → Timeout → Disconnect → Recovery | Escalating severity |

Each scenario reuses existing FailureProfile/InjectionRule types — no new failure modes.

## Block 3 — Continuous Certification

Automatic invariant checking after every step:

| Invariant | Check | Source |
|-----------|-------|--------|
| `assertGatewayHealthy()` | GatewayRuntime state is the expected state | GatewayRuntime |
| `assertWalletConsistent()` | Wallet balance matches position P&L | WalletRuntime |
| `assertNoDuplicateTrades()` | Each fill appears exactly once | ExecutionGateway |
| `assertReplayHash()` | Hash of replayed state matches hash of exchange | ReplayEngine |
| `assertChaosTrace()` | All injections have corresponding ChaosTrace events | ChaosTraceRuntime |
| `assertMetrics()` | Telemetry SLI counters are monotonic | RuntimeTelemetry |

## Block 4 — SLO Certification

Measured timing SLOs for each recovery phase:

| SLO | Target | Measured By |
|-----|--------|-------------|
| Gateway recovery | < 5s | GatewayRuntime state change |

| Wallet sync | < 1s | WalletRuntime sync |
| Chaos detection | < 500ms | ChaosTrace creation timestamp |

## Block 5 — Incident Bundle

After each campaign, generate:

```
Incident/<campaign-name>/
├── ChaosTrace.json        — All trace events from the campaign
├── ReplayCursor.json       — Current replay cursor position
├── EventJournal.db         — SQLite journal snapshot
├── Metrics.json            — Telemetry snapshot
├── HealthSnapshot.json     — HealthAggregator snapshot
├── StructuredLogs.json     — Log entries for the incident period
└── CertificationReport.json — Pass/fail per assertion
```
